# 主担当の進め方（主担当が読む文書）

- この文書は、段階①-2・段階②-1・段階②-2・段階③ の主担当向けです。段階①-1（下調べ）のセッションは、CLAUDE.md の「段階①-1 の決まり」だけに従います。
- 段階・役割・モデルの対応は CLAUDE.md だけにあります。この文書は、段階の名前と役割名で書きます。
- 守ることの細目は 〈決まりの文書〉。今の状態と次の一手は HANDOFF.md。食い違うときは、CLAUDE.md → この文書 → 〈決まりの文書〉 の順に従います。

## 1. 最初の 5 分

1. 状態を確かめる：`git branch --show-current`、`git status`、`git fetch`。
2. 読む：CLAUDE.md → HANDOFF.md の §0・§3・§4.2 → 〈決まりの文書〉 の守ること → 関係する計画書。全部は読まない。
3. 段階を照らす：HANDOFF.md の §0 の「今の段階」と、このセッションの設定（モデル名、〈合図の語〉 の知らせ）と、今の枝。合わなければ、作業の前に利用者に伝える。段階①-2 の最初は、wip の索引の「段階①-2 への引き継ぎ」を HANDOFF.md の §0 に写す。
4. 今の状態を 3 行で言い直す。食い違いがあれば、依頼に入る前に利用者に伝える。
5. 足りないことだけを聞く（多くても 3 つ）。調べて分かることは聞かない。

新しいセッションに貼る一言は docs/operating-kit/prompts.md。

## 2. 段階ごとの進め方

### 2.1 段階①-2（整備）
- 最初に、wip の索引の引き継ぎを HANDOFF.md の §0 に写す。関わり方を照らす（記録が無ければ一つの問いで聞く）。
- 材料を読み、自由に考察・分析・発想・デザインができるよう、文書と置き場を整える（索引、構造の地図の「今の状態」、思いつきの重なりをまとめる（判定はしない）、材料を置く場所）。
- 計画、段の分け方、案の採否は決めない。途中の思いつきは 〈思いつきの置き場〉 に一行。
- ワークフロー：調査担当で読み足し、検討担当に整え方の案を広げさせ、疑わせる。判定は主担当。

### 2.2 段階②-1（考察と発想）
- 最初に、関わり方を照らす（記録が無ければ一つの問いで聞く）。読むのは、段階①-2 で整えた文書（索引・地図）と 〈思いつきの置き場〉。
- 案を観点ごとに広げる（§4.1）。足りない材料は、調査担当で読み足し、wip に足してよい。
- 行程の判断（どの観点で広げるか、二周目を回すか、終わりの目安を満たしたか）は主担当がする。しないのは、案の採否と箱分け（判定は段階②-2）、順位付け、計画、段の分け方。制約は段階②-2 の判定で当てる。
- ワークフローの結果を読んだら、要約する前に、全部の案を `docs/wip/<②-1 を始めた日>/ideas/` に書いてコミットする（セッションが替わると journal.jsonl は読めない）。
- 終わりの目安（§4.2）を照らし、結果を案の一覧に書いてから、「移ってよい」と提案する。HANDOFF.md の §0 の「次の段階」には、案の一覧のパスを書く（段階②-2 はそこから読む）。
- ワークフロー：検討担当（案を広げる・疑う。§4）、調査担当（読み足す）、関わり方 (B) なら相談役（§3）。

### 2.3 段階②-2（計画とデザイン）
- 最初に、HANDOFF.md の §0 にある案の一覧を読み、制約（〈決まりの文書〉 の守ること・〈大きな決めごとの一覧〉・〈重い層〉）を当てて、案を箱に分ける（§5）。判定は、案の一覧の判定の表（id・箱・理由一行・もう一度見る条件）だけに書き、コミットする。案そのものは書き換えない。
- 計画に入れる案は、主担当が「すぐ」と「次」から選び、理由を計画書の「考察から変えたところ」に書く。大きな決めごとに当たるものは、止まって聞く。
- 計画書を 〈計画書の形〉 で書く。段はおおまかでよい（段階③ の始めに細かくする）。
- 画面が変わるなら、見本を 〈見本の置き場〉 に作る（〈コードの場所〉 は変えない）。
- 大きな決めごと（〈大きな決めごとの一覧〉）は、困ったこと・案・おすすめで聞き、答えを HANDOFF.md の §4 に写す。
- 計画を組む途中で、広げ直しが要るほどの抜けが分かったら、段階②-1 へ戻ることを提案する。小さな抜けなら、その場で案を足し、出どころを「段階②-2 で足した」と書く。
- 「移ってよい」の提案には、箱ごとの数と、「後」「見送り」にした案（とくに 〈思いつきの置き場〉 から来た案）の一覧を添える。利用者が箱を変えたら、HANDOFF.md の §4 に写す。
- ワークフロー：調査担当（入口の確かめ）、検討担当（計画の案を疑う）、関わり方に応じて相談役（§3）。

### 2.4 段階③（実装）
- §7 の流れで進める。相談は CLAUDE.md の「相談の手続き」（利用者が 〈合図の語〉 と送った論点だけ）。
- 途中で大きな思いつきが出たら 〈思いつきの置き場〉 に書き、計画を大きく変えるものなら、段階②-2 へ（広げ直しが要るなら段階②-1 へ）戻ることを提案する。

### 2.5 段階を移る
- 「移ってよい」の提案に書くこと：できたもの、確かめたこと・確かめていないこと、残り、次の段階の範囲、次の段階の関わり方の問い（おすすめ付き）。
- 移る前に HANDOFF.md（§0 の「今の段階」と引き継ぎ）を直し、作業枝にコミットし、`git fetch` してから push する。新しいセッションは、同じフォルダか作業枝で始めてもらうよう、一行添える。

## 3. 関わり方の選び方と運び方（段階①-2・段階②-1・段階②-2）

| 関わり方 | 向く場面 | 利用枠の重さ |
|---|---|---|
| (A) 主 | 新しい系統の機能や画面を一から組む。今の形から外れた発想がほしい（とくに段階②-1） | いちばん重い（その段階のセッション全部）。止まりやすい |
| (B) 総合 | 案が一つにまとまり、方向・抜け・別案を一度に見てほしい。段階②-1 では、案の一覧ができ、抜けている観点・広げ足りない所を見てほしい | 中くらい（3〜5 体に一〜二回） |
| (C) 要所 | 今の仕組みに沿った計画で、決めきれない論点が少しだけある | 軽い（論点ごとに数体） |
| なし | 小さな計画、文書の整理、前例どおり | 使わない |

- **重ね方**：(B) と (C) は重ねてよい（途中は (C)、案がまとまったときと次の段階へ移る前に (B) を一回）。段階②-1 では (C) を使わないので、(B) だけ。(A) のときは、(B)(C) を (A) の段階の相談役で行う。
- **(A) のとき**：主担当の仕事と決まりは変わらない。区切りごと（ワークフローの結果を読んだあと、決めごとのあと、長い作業の前）に HANDOFF.md へ書いてコミット・push する。
- **(B) のとき**：3〜5 体に、観点を分けて頼む（方向・抜け・別案・危うさ・使う人の目）。時期は、案が一つにまとまったときと、次の段階へ移る前。聞かずに行い、結果を知らせる。読み方は「相談の手続き」の 3 と 4 の 1〜2。ひな形は docs/operating-kit/workflows/consult.js。
- **段階②-1 の (B)**：案の一覧を丸ごと見てもらう（観点は、抜けている観点・広げ足りない所・別の問いの立て方）。時期は、一周目の案を書いたあと、または移る前。相談役が出した新しい案は、出どころを (B) としてカードに足す（判定しない）。HANDOFF.md の §4.2 の「主担当の判定」の欄には、受け止め（例：二周目に足す観点）を書く。
- **(C) のとき**：「相談の手続き」の 1〜4。段階①-2・②-2 では、問いは「相談しますか」で、返事は「はい」で足りる。
- **どれでも**：相談役と検討担当の結論は決定ではない。判定は主担当、大きな決めごとは利用者。

## 4. 自由に発想する（段階②-1）

### 4.1 広げ方
- 発想と判定を分ける。広げるのは段階②-1、判定は段階②-2。二つの段階をまとめるときも、広げる周と判定の周を分け、判定の前に案の一覧をコミットする。
- 広げるときは「今の決まりでは無理」と書かず、案を広げる。制約は、段階②-2 の判定で当てる。
- 観点ごとに広げる（例：使う人の場面・逆にする・極端にする・ほかから借りる・組み合わせる・制約を一つ外す）。一つの観点に 3〜5 案。
- 案の書き方：何を（一文）／どこに入れる（ファイルと関数。見当でよい）／どんな場面で効く／危ないこと／確かめ方。出た観点と、種類（奇抜・やめる・減らす・組み合わせる・制約を外す・そのほか）も書く。
- 一周で終わりの目安（§4.2）の 3 に届かなければ、空いた観点・少ない種類に向けて観点を選び直し、二周目を回す。二周目には一周目の案の短い名前を渡し、重ならない案を出させる。

### 4.2 終わりの目安（「移ってよい」と言えるとき）
1. 網羅：どの観点にも案が一つ以上ある（空いた観点が無い）。
2. 種類：今の形から外れた奇抜な案・やめる（減らす）案・今あるものを組み合わせる案が、それぞれ一つ以上ある。
3. 量か飽和：案が 20 前後に届いた。または、二周目に出た新しい案（一周目と重ならないもの）が 3 つ以下だった。
- 1 と 2 は両方、3 はどちらか一つを満たす。
- 照らすのは主担当。ワークフローが返す数（観点ごと・種類ごと）は材料で、種類は広げた担当の自己申告なので、主担当がカードを読んで付け直してよい（付け直したら案の一覧に書く）。二周目の案が一周目と重なるかも、主担当が見分ける。
- 照らした結果（数と、主担当の照らし。どれを満たし、どれを満たさないか）は、案の一覧に書く。
- 満たさないまま移るなら、満たさない点と理由を「移ってよい」の提案に書き、利用者が決める。

### 4.3 思いつき
- 段階②-1 の対象の外の思いつきは 〈思いつきの置き場〉 に日付つきで一行。

## 5. 判断する

- **案の判定**（段階②-2）：段階②-1 の案に制約を当て、箱に分ける。すぐ（小さく、今ある仕組みで作れて、効果が大きい）／次（段を分ければ入る）／後（大きい、または今は要らない）／見送り（危ない、効果が薄い、今の決まりに反する）。理由は一行ずつ。票や点数で分けない。
- **小さな決め**：主担当が決めて、理由を計画書の「決めごと」か HANDOFF.md の §4 に一行（案の箱分けは、案の一覧の判定の表）。
- **大きな決め**（〈大きな決めごとの一覧〉）：止まって利用者に聞く。書き方は「困ったこと・案・おすすめ」。おすすめは一つ。質問は三つまで。
- **相談役を使うとき**：段階③ は CLAUDE.md の「相談の手続き」、段階①-2・②-1・②-2 は関わり方（§3）。段階③ で相談が終わったら、結論を HANDOFF.md の §4.2 に写してから確認の一文で聞き、「はい」を待ってから次の行程に進む。
- 票や点数で決めない。利用者の答えは、日付つきで HANDOFF.md §4 に写す。

## 6. 仕事を分ける

| 役割 | 何をする | 何をしない |
|---|---|---|
| 主担当 | 計画・設計・判断・仕様・差分の確認・確かめ・利用者への説明。〈重い層〉 を書く | — |
| 実装担当 | 段階③：仕様が決まった小さな実装。段階①-2：文書の機械的な直し | 仕様に無い判断、〈重い層〉、保存の形の変更、git の操作 |
| 調査担当 | ワークフローの中で、読んで集める | 編集、判定 |
| 検討担当 | 段階①-2・②-1・②-2 のワークフローの中で、案を広げる・疑う | 編集、判定、決定 |
| 相談役 | 段階③ は 〈合図の語〉 の論点、段階①-2・②-2 は関わり方 (B)(C)、段階②-1 は (B) のとき。読み取り専用の相談 | 編集、決定、自分でのワークフロー起動 |

**実装担当に渡す大きさの目安**（超えるものは、仕様を分けるか、主担当が書く）：触るファイルは 1〜3、関心は一つ。非同期の流れ、面どうしのやりとりの型、保存の形は主担当が決めて書く。〈重い層〉 は触らせない。

仕様の形は docs/operating-kit/spec.template.md。仕様は `docs/wip/<日付>/specs/<名前>.md` に置き、「---」から下を渡す。返ってきた結果は、主担当が `git diff` を全部読み、改行が変わっていないかも見てから利用者に伝える。

## 7. 段階③ の流れ

1. 段階②-2 の計画書を読み、段を細かくする。計画が大きく違っていたら、段階②-2 へ戻ることを提案する。段階の外の小さな仕事は、計画書なしでよい。
2. 段ごとに作業枝の中で作る。
3. 段の仕様を書き、実装担当に頼む（§6）。
4. `git diff` を全部読む。〈型検査〉。必要なら画面の確かめ。
5. 〈重い層〉 を変えたら、ビルドを確かめたかを必ず書く。確かめた範囲と確かめていないことを分けて書く。
6. 計画書の段の表を、実装の形に直す。HANDOFF.md を直す。
7. 作業枝にコミットし、`git fetch` してから push。PR は頼まれたときだけ。

## 8. 引き継ぎ（閉じるとき・主担当が替わるとき・段階を移るとき）

HANDOFF.md に書く（形は docs/operating-kit/HANDOFF.template.md）。長くしない。

1. 今の段階（段階・関わり方・作業枝・次の段階とその範囲）
2. 今どうなっているか（HEAD、未コミットの変更、動いているもの）
3. 次に何をするか（一つ。理由を一行）
4. 利用者に聞くこと（おすすめ付き）
5. 確かめたこと・確かめていないこと（分けて）
6. 返事待ちの相談（止まるときに §0 の 4 に一行。返事が来たら消す）

## 9. 書き方

- モデル名は CLAUDE.md だけに書く。ほかの文書とコミットは、段階の名前と役割名。関わり方は記号 (A)(B)(C)・なし で書く。
- 丸数字の段階には必ず「段階」を付ける。「段階②」とだけ書くときは、段階②-1 と ②-2 の両方を指す。計画書の中の小分けは「段」。
- 日付は絶対日付。行番号は「見た時点の行」と書く。
- 運用の決まりを変えたら、docs/operating-kit/ のひな形も同じコミットで合わせる。
