# 〈〉の一覧と、調べ方・聞き方

（正本：honeycomb-browser-grok の `docs/operating-kit/README.md` §4.3。版は SKILL.md の頭）

- 調べて分かるものは調べる。聞くのは三つまで（おすすめ付き）。ふつうは「モデル三つ」「作業枝とコミットの決まり」「戻すのが重い所」で足りる。
- モデルの呼び名は、入れる先では CLAUDE.md の中だけに書く。下の「おすすめの例」は、このスキルを書いた時点（2026-10-15）の例。そのときのモデルの並びに合わせて読み替える。
- 〈小〉〈主〉〈上〉 は二通りに入れる。`model: "〈…〉"` の形の所は Agent ツールの指定（例 `haiku`・`opus`・`fable`）。それ以外の所（段階の表のセッションの欄、関わり方の合図の言葉、説明の文）は呼び名（例 `Haiku 5.5`・`Opus 5.5`・`Fable 5.1`、合図なら `Fable 主`）。
- 〈決まりの文書〉 が CLAUDE.md の中の節になるときは、CLAUDE.md の冒頭の「食い違うときの順」を「CLAUDE.md → docs/main-agent.md」の二つにする（同じ文書を二度並べない）。
- ひな形の中で 〈〉 は、下の表の名前のためだけに使っている。表に無い 〈…〉 を見つけたら、型の誤りなので、正本に知らせる。
- 〈型検査〉 などのコマンドは、` で囲まずにコマンドだけを入れる（ひな形の中に、コードの枠の中で使う所があるため）。

| 〈〉 | 入るもの | 調べ方 | おすすめ（聞くとき） |
|---|---|---|---|
| 〈小〉 | 調査担当・実装担当・段階①-1 のセッションのモデル（安く速いもの） | — | 例：`haiku` |
| 〈主〉 | 主担当・検討担当・相談役（代わり）のモデル | 今のセッションのモデル（システムの文） | 例：`opus` |
| 〈上〉 | 相談役（基本）と、関わり方 (A) の段階のセッションのモデル（いちばん深く考えるもの） | — | 例：`fable`。使えないなら 〈主〉 と同じにし、関わり方の (A)(B) を外す |
| 〈主の effort〉 | 段階③ のセッションの effort | — | 例：`xhigh` |
| 〈合図の語〉 | 相談の許しの語（ワークフローを起こす語） | — | `ultracode` |
| 〈名前〉 | リポジトリの名前 | README の題、`package.json` の `name`、フォルダ名 | — |
| 〈正本〉 | 正本の repo | `git remote -v` | 一つしかなければそれ。複数なら聞く |
| 〈作業枝〉 | コミットと push をしてよい枝 | `git branch --show-current` | 既定の枝の上にいるなら、作業用の枝を作るかを聞く |
| 〈入れない枝〉 | 入れてはいけない枝 | `git symbolic-ref refs/remotes/origin/HEAD`、無ければ `main` か `master` | — |
| 〈型検査〉 | 編集のあとに通す確かめのコマンド | `package.json` の `scripts`（typecheck・lint・test）、Makefile、`pyproject.toml` など | 無ければ「なし（読む確かめだけ）」と書く |
| 〈コードの場所〉 | 段階②-1・②-2 で変えない所 | `src/`・`app/`・`lib/` など | — |
| 〈重い層〉 | 実装担当に触らせない、戻すのが重い所 | ネイティブのコード、DB の移行、保存の形、外の API との約束 | 無ければ「保存の形」 |
| 〈決まりの文書〉 | 守ることの細目 | CONTRIBUTING、`docs/` の決まりの文書 | 無ければ CLAUDE.md の「作業の始め方」に数行で書く |
| 〈大きな決めごとの一覧〉 | 止まって使う人に聞くもの | 同じ | 無ければ型の既定（保存の形を変える、外への送信を増やす、〈重い層〉 を段の予定より前に変える、既存のデータを移す、既存の数〈上限・秒数〉を変える）を CLAUDE.md に書く |
| 〈計画書の形〉 | 段階②-2 で書く計画書の見出し | 既にある計画書 | 無ければ `docs/plan-<名前>.md` を次の見出しで：1 何を作るか／2 どこから呼び出すか／3 今あるものを使う／4 守る決まり／5 決めごと／6 保存先／7 段／8 考察から変えたところ／9 実装中に計画にない大きな決めごとが出たら |
| 〈見本の置き場〉 | 画面の見本 | 既にある見本のフォルダ | `docs/mocks/` |
| 〈思いつきの置き場〉 | 判定の前の思いつき（段階①-1 を除いて、だれでも一行ずつ書く） | 既にあればそれ | `docs/ideas-inbox.md`（無ければ作る） |
| 〈見送りの台帳〉 | 判定のあとで計画に入れなかった案（段階②-2 の主担当だけが書く。理由ともう一度見る条件つき。段階②-1 が読む） | 既にあればそれ | `docs/ideas-shelf.md`。入れるときは作らず、段階②-2 で初めて要るときに作る。小さなリポジトリなら、〈思いつきの置き場〉 の中の節「後と見送り」でよい |

関わり方の合図の言葉（CLAUDE.md の「関わり方」の表）は「〈上〉 主」「〈上〉 総合」「〈上〉 要所」「〈上〉 なし」の形。〈上〉 には、利用者が呼びやすいモデルの呼び名（例：`Fable`）を入れる。
