# 型の芯と、変えてよい所

（正本：honeycomb-browser-grok の `docs/operating-kit/README.md` の §1・§2・§5。版は SKILL.md の頭。§2 の 9 と、段階②-1・②-2 の分け方は、このブランチの直しで、正本へはまだ入れていない。ほかのこのブランチの直しは SKILL.md の頭の「型の版」の注）

## 1. 何のための型か

一人の判断役（主担当）が、下調べ・整備・考察と発想・計画とデザイン・実装を段階ごとに新しいセッションで進め、要所だけで上位のモデルに相談する、そのための決まりの組み立て。ねらいは三つ。判断がぶれないこと（判断は一人、票では決めない）。使う人が舵を握ること（モデルの切り替え・相談の許し・大きな決めごとは使う人）。セッションが替わっても続けられること（橋渡しは一つの再開用のメモ）。

## 2. 型の芯（変えない方がよい所）

1. **段階を分け、段階ごとにセッションを替える。** 段階ごとに、目的・できあがるもの・しないこと・中で働く役割を表にする。橋渡しは再開用のメモ（HANDOFF.md）一つ。
2. **判断は一人。** 主担当だけが判定する。調査担当（集める）・検討担当（案を広げる・疑う）・相談役（上位のモデルの意見）・実装担当（仕様どおりに作る）は、判断しない。
3. **相談は使う人の許しで。** 合図の語を決め、主担当が「相談しますか」と聞いた論点への返事か、使う人が論点を名指しした頼みのときだけ相談する。説明・引用・否定の中の語では動かない。
4. **票で決めない。** 相談の結論は決定ではない。割れたら、両側の根拠（ファイルと行）を主担当が自分で読んで判定する。根拠の無い答えは使わない。
5. **止まる目安は二つの掛け算。** 決めきれない案が二つ以上残る、かつ、選び違えると戻すのが重い。どちらかだけなら、主担当が決めて理由を一行書く。
6. **記録してから止まる。** 使う人の答えと、相談の結論を分けて、日付つきで書く。返事待ちは、止まるときに書いてコミットしておく。
7. **モデルと effort は使う人が切り替える。** 主担当は切り替えない。セッションの始めに、記録と設定を照らす。
8. **モデル名は一か所だけ。** モデルとの対応は CLAUDE.md だけに書き、ほかの文書とコミットは役割名で書く。モデルが替わっても、直すのは一か所で済む。
9. **広げる行程では絞らない。** 案を広げる行程（段階②-1、または段階をまとめたときの広げる周）では、採否・箱分け・順位を書かない。判定（箱分け）は、案の一覧を残して（コミットして）から主担当がする。小さな決め（docs/main-agent.md §5）には掛からない。

## 3. 段階（既定の形）

| 段階 | セッション | 目的 | しないこと |
|---|---|---|---|
| 段階①-1 下調べ | 〈中〉・合図の語をセッション全体 | 考察・発想の土台になる材料を集め、`docs/wip/<日付>/` に置く | wip の外に書く、決める、計画 |
| 段階①-2 整備 | 〈主〉・合図の語をセッション全体 | 材料で、自由に考察・発想できるよう文書と置き場を整える | 計画、案の採否、コード |
| 段階②-1 考察と発想 | 〈主〉（関わり方 (A) なら 〈上〉）・合図の語をセッション全体 | 案を自由に、多くの観点から広げ、`docs/wip/<日付>/ideas/` に置く | 判定（箱に分ける・採否・順位）、計画、コード |
| 段階②-2 計画とデザイン | 〈主〉（関わり方 (A) なら 〈上〉）・合図の語をセッション全体 | 案を判定し、計画書と画面の見本を、おおまかに組む | 実装、段の細かい仕様 |
| 段階③ 実装 | 〈主〉・〈主の effort〉（合図の語は依頼ごと） | 計画を段ごとに作って確かめる | 計画にない大きな決めごとを自分で決める |

関わり方（段階①-2・②-1・②-2 で上位のモデルがどう関わるか）：(A) 主＝その段階のセッションを 〈上〉 にする／(B) 総合＝まとまった案を丸ごと見てもらう／(C) 要所＝迷う論点だけ相談する／なし。

## 4. 変えてよい所・変えない方がよい所

| 変えてよい | 変えない方がよい |
|---|---|
| 段階の数と名前（小さなリポジトリなら段階①-1 と ①-2、段階②-1 と ②-2 をそれぞれまとめる。実装だけなら段階③ だけ。仕事ごとにまとめるときは docs/main-agent.md §2.6） | 判断は一人、票で決めない（§2 の 2・4） |
| 各段階のモデルと effort、合図の語をセッション全体に入れる段階 | 相談は使う人の許しで、合図の語は説明の中では動かない（§2 の 3） |
| 関わり方の数（(A)(B)(C)・なし のうち使わないものを外す。〈上〉 が使えないなら (A)(B) を外す） | モデルと effort は使う人が切り替える（§2 の 7） |
| 相談の体数（基本 5 体前後）と、一つのワークフローの上限（10 体。変えたら docs/operating-kit/workflows/*.js の上限も直す） | 記録してから止まる、答えと相談の結論を分ける（§2 の 6） |
| 実装担当の大きさの目安、仕様の欄、捨てる前提の試しの時間の区切り（30 分ほど）と 〈試しの枝〉 の名前の形 | 止まる目安の掛け算（§2 の 5） |
| 守ることの細目（〈決まりの文書〉 の中身） | モデル名は一か所（§2 の 8） |
| 広げる行程の終わりの目安の数（重なりを除いて 30 前後、最後の周の新しい案 3 つ以下、ふつうは一周 4 観点で二周以上）と、必ず入れる案の種類（奇抜・やめる・減らす・組み合わせる・制約を外す・作らない） | 広げる行程では絞らない、判定は案の一覧を残してから（§2 の 9） |
