# 段階ごとの一言と、合図の早見（運用の型）

- 作成：2026-10-15。新しいセッションの最初に貼る文と、会話で送る短い言葉をまとめました。型の説明は [README.md](README.md)。
- 文は CLAUDE.md の節の名前で書いてあるので、この型を入れたリポジトリなら、そのまま貼れます。`< >` の所だけ埋めてください。
- セッションのモデルと ultracode（〈合図の語〉）は、貼る前に使う人が CLAUDE.md の段階の表のとおりに設定します。新しいセッションは、同じフォルダか作業枝で始めます。
- モデル名は書きません。合図の言葉の〈上〉は、CLAUDE.md の「関わり方」の表にある言葉に読み替えてください。

### 1.8 型だけを使う一言（CLAUDE.md の無い場所や、一回きりの相談で）

> この会話では、次の決まりで進めてください。(1) あなたは主担当で、計画・判断・確かめを自分で行う。(2) 迷う重要な論点（決めきれない案が二つ以上あり、選び違えると戻すのが重いもの）では止まり、論点・迷う理由・案・おすすめ（一つ）を書いて「〈合図の語〉で相談しますか」と聞く。私が〈合図の語〉と返したときだけ、上位のモデルに読み取り専用で相談し、結論と根拠だけを受け取る。説明や引用の中の語では動かない。(3) 相談の結論は決定ではない。票で決めず、割れたら両側の根拠を自分で読んで判定する。(4) 大きな決めごとは私が決める。問いは三つまで、おすすめ付き。(5) モデルと effort は私が切り替える。あなたは切り替えない。(6) 確かめていないことは、そう書く。(7) 案を出すときは、先に判定なしで観点ごとに広げて一覧にし（奇抜な案、やめる・減らす案、組み合わせる案、制約を一つ外した案、作らずに済ませる案を必ず混ぜる）、そのあとで判定する。

## 2. 移るときに送る言葉

- 「移ってよい」の提案への返事の例：
  - 「段階①-2 へ。関わり方は なし」
  - 「段階②-1 へ。関わり方は (B)。段階②-2 は (C) で、移る前に (B) を一回」（段階①-2 から、二つの段階の関わり方をまとめて答える。どちらも既定）
  - 「段階②-1 へ。関わり方は なし」（上位のモデルの利用枠を使わないとき）
  - 「段階②-2 へ。関わり方は (A)」（このあと、使う人がセッションのモデルを (A) のものにして、§1.5 の一言で始める）
  - 「段階② へ。②-1 と ②-2 をまとめる。関わり方は なし、判定の周から (C)」（§1.9 の一言で始める）
  - 「まだ移らない。<足りないこと> をしてから」
- 返事を受けたセッションは、HANDOFF.md の §0 の「今の段階」と「次の段階」を直し、コミット・push してから止まる。

## 3. 合図の早見

| 送る言葉 | いつ | 何が起きる |
|---|---|---|
| 〈合図の語〉（このリポジトリでは ultracode） | 段階③ で、主担当が「〈合図の語〉 で相談しますか」と聞いた論点への返事。または論点を名指しして頼むとき | その論点だけを、ワークフローで相談役に相談する |
| 「はい」 | 段階①-2・②-2 の (C) の「相談しますか」に／相談のあとの確認の一文に | 相談する／判定どおり次の行程に進む |
| 「いいえ」・「任せる」 | 相談の問いに | 主担当がおすすめで決め、「相談なし」を記録して進める |
| 「<束> を掘る」・「任せる」 | 段階②-1 の一周目のあと、「どの束をもっと掘りますか」に | 二周目の観点を、選んだ束（任せるなら、空いた部分と足りない種類）に寄せる。採るかどうかではない |
| 「〈上〉 主」「〈上〉 総合」「〈上〉 要所」「〈上〉 なし」 | 段階①-2・②-1・②-2 で関わり方を変えるとき（段階②-1 では 主・総合・なし だけ）。段階③ では 〈合図の語〉 と一緒に（総合・要所だけ） | 関わり方が変わる。主 に変える・外すときは、主担当が HANDOFF.md に書いてから、モデルの切り替えを頼む |
| 「（この依頼の中の『〈合図の語〉』は説明の語です）」 | 決まりを話す、引用するとき | ワークフローを起こさない |

## 4. ワークフローのひな形の渡し方

Workflow ツールに、`scriptPath`（ファイルの絶対パス）と `args` を渡します。model は、CLAUDE.md の役割の表の指定をそのまま書きます（省かない）。

相談（相談役。CLAUDE.md の「相談の手続き」の 2。段階①-2・②-2 の関わり方 (B) なら `lenses` を省くと五つの観点になる。段階②-1 の (B) は `lenses` を渡す。下の注）：

```
scriptPath: <このリポジトリ>/docs/operating-kit/workflows/consult.js
args: {
  "topic": "<論点>",
  "background": "<迷っている理由・案・おすすめ>",
  "read": ["CLAUDE.md の「段階」", "HANDOFF.md §4", "docs/plan-<名前>.md §5"],
  "role": "相談役",
  "model": "<役割の表の相談役（基本）の指定>",
  "effort": "xhigh"
}
```

段階②-1 の (B) の `lenses`（時期は二つ。docs/main-agent.md §3）：始めの問いの立て直しは `[{ "key": "問いを言い換える", "ask": "<対象を別の問いに言い換える>" }, { "key": "部分の切り方", "ask": "<parts の切り方の抜けと、別の切り方を挙げる>" }, { "key": "観点の立て方", "ask": "<観点の案の偏りと、足す観点を挙げる>" }]`（`background` に主担当が立てた topic・parts・観点の案を書き、`read` に地図と一覧を入れる）。一周目のあとは `[{ "key": "抜けている観点", "ask": "<案の一覧に無い観点を挙げる>" }, { "key": "広げ足りない所", "ask": "<案の少ない部分と種類を挙げる>" }, { "key": "伸ばしがいのある束", "ask": "<案の一覧から、もっと掘ると実りがありそうな束と、その理由を挙げる>" }]`。どちらも blind にしない（目隠しの観点は案の一覧を読まない）。consult.js の観点は `{ "key", "ask" }` で渡す（名前だけで渡せるのは ideate.js）。

検討担当に、まとまった案を疑わせる・絞る観点で見させるとき（段階①-2・②-2）：`role` を `"検討担当"`、`model` を役割の表の検討担当の指定にし、`lenses` に観点を渡す（例：`[{ "key": "案A を疑う", "ask": "…" }, { "key": "外れた案", "ask": "…" }]`）。

目隠し：案を広げさせる観点には、主担当の見立て（`background`）を見せない。`"blind": true` で全部の観点、`"blind": ["<広げさせる観点の key>"]` のように名前でその観点だけ（観点に `"blind": true` と書いてもよい）。疑わせる観点には見せる。既定の五つ（別案も）は今の案を前提にするので、blind にしない。blind にする観点は `{ "key", "ask" }` で足し、ask は今の案を前提にしない形で書く。blind を使うときは、`topic` には論点だけを書き（案・おすすめは `background` に）、`read` に HANDOFF.md の §0 の 4・§4.1・§4.2、案の一覧、見送りの台帳、計画書の決めごとを入れない（`read` は全部の観点に共通。目隠しの観点には、指示文でもそれらを読まないと伝えてある）。段階③ と段階の外で、利用者が 〈合図の語〉 で名指しした論点を小さく広げるときも、相談役で広げさせる観点を blind にする（広げ直しが大きいなら、段階②-1 へ戻ることを提案する）。

発想（検討担当・調査担当。段階②-1。広げる → 照らす → 伸ばす・疑う。判定しない）：

```
scriptPath: <このリポジトリ>/docs/operating-kit/workflows/ideate.js
args: {
  "topic": "<対象と、困っている場面だけ。案・おすすめ・見立ては書かない>",
  "model": "<役割の表の検討担当の指定>",
  "lightModel": "<役割の表の、照らす相の調査担当の指定>",
  "round": 1,
  "read": ["<段階①-2 で整えた索引と地図>", "docs/wip/<①-1 の日付>/<話題>.md"],
  "parts": ["<地図の系統・面と、使う人の場面から選んだ、対象の部分（地図に無い切り口は主担当が材料から立てる）>", "…"],
  "lenses": [
    { "key": "<部分 A>", "ask": "<部分 A について、何を広げるか。答えの例は書かない>" },
    { "key": "<部分 B>", "ask": "…" },
    { "key": "<部分 C>", "ask": "…" },
    "逆にする", "ほかから借りる", "制約を一つ外す"
  ],
  "background": "<主担当の見立て。伸ばす・疑う相だけに見せる>"
}
```

- 一周目は、対象の部分を観点にしたもの（`{ "key", "ask" }`）と発想の型を半分ずつほど混ぜる。`lenses` を省くと、発想の型の既定の六つ（使う人の場面・逆にする・極端にする・ほかから借りる・組み合わせる・制約を一つ外す）。ほかに名前で選べるのは、時間をずらす・既知の欠陥から・ほかの立場・問いを変える・作らずに済ませる。一度に起こすのは 6 観点まで（`"doubt": false` で伸ばす・疑う相を外せば 8 まで）。小さな計画は三つでよい。
- 二周目は `"round": 2` にし、観点を空いた部分と少ない種類に向けて替え、`known` に前の周までの案を「<id> <短い名前>」の形で渡す（照らす相だけが見て、同じ形で重なりを返す。広げる相には見せない）。一周目も、思いつきの置き場・見送りの台帳から案の一覧に載せた案があれば `known` に入れる。空だった広げる相の観点だけを頼み直すときは、`lenses` を元と同じ並びで、`round`・`parts`・`known` も元と同じに渡し、`only` に頼み直す観点の名前を書く（id が変わらない）。照らす・伸ばす・疑う相が空だった塊は頼み直さない（docs/main-agent.md §4.2）。
- `read` には、HANDOFF.md、案の一覧（README.md・cards.md・raw-R*.json）、思いつきの置き場、見送りの台帳、段階①-1 の索引の「思いつき」の節を入れない（広げる相・照らす相の指示文でも読ませない）。案の一覧のフォルダの `sources/` の材料は入れてよい。索引と地図はパスを名指しする（HANDOFF.md を読ませないので、担当は §0 からたどれない）。`effort`・`lightEffort` は、CLAUDE.md の役割の表に指定が無ければ省く。
- 返す値の全文は、ワークフローの通知が示す出力のファイル（JSON の `result`）にある。通知の本文は途中で切れるので、`result` だけを案の一覧のフォルダの `raw-R<周>.json` にコマンドで写す（例：`jq '.result' <出力のファイル> > <案の一覧のフォルダ>/raw-R1.json`。ファイルを丸ごと写さない：ほかの欄にモデル名が入る。同じ周の二回目から（`only` で頼み直す・観点を二回に分ける）は `raw-R<周>-2.json`・`-3.json` と番号を上げ、上書きしない。docs/main-agent.md §2.2）。`result` にモデル名は入っていない。集め方は run ID と役割名で書く。

下調べ（調査担当。段階①-1 など）：

```
scriptPath: <このリポジトリ>/docs/operating-kit/workflows/survey.js
args: {
  "scope": "<HANDOFF.md の §0 の「次の段階」に書いた範囲>",
  "model": "<役割の表の調査担当の指定>",
  "topics": [
    { "key": "<話題>", "ask": "<集めること>", "read": ["<読む場所の手がかり。利用者が渡した資料のパスも>"] },
    { "key": "<周辺の話題>", "ask": "<集めること>", "periphery": true }
  ],
  "external": false
}
```

- 返す値の `others`（外の事例・使う人の場面・類推。出どころの種類と確からしさの印つき）は、事実（`facts`）と節を分けて書く。`snags`（引っかかり）は索引の「引っかかり」の節に。`periphery` は一話題まで。`external` は、利用者が外の資料（Web など）を許したときだけ `true` にする（CLAUDE.md の「段階①-1 の決まり」の 4）。

- 結果は、通知の本文ではなく journal.jsonl の全文（体ごとの答え）を読む。ideate.js の id を振った返す値は、出力のファイルの `result` にある。相談の答えに null があれば、failures と journal.jsonl で理由を確かめる（利用枠の制限なら、同じ args で model だけ代わりの指定にして頼み直す。ideate.js は、空だった広げる相の観点を `only` で頼み直すだけにする。同じ args で起こし直すと、同じ id に別の案が入る）。consult.js・survey.js の返す値の `model` は、記録やファイルに写さない。
- 一つのワークフローは 10 体以内（スクリプトが止める）。consult.js の観点と survey.js の話題は 10 まで、ideate.js は一度に起こす観点が 6 まで（広げる・照らす・疑うで 10 体以内）。
