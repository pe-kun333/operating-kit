## 2. 移るときに送る言葉

- 「移ってよい」の提案への返事の例：
  - 「段階①-2 へ。関わり方は (A)」（標準。このあと、使う人がセッションのモデルを (A) のものにして、§1.2 の一言で始める）
  - 「段階②-1 へ。関わり方は (A)。段階②-2 も (A)」（段階①-2 から、二つの段階の関わり方をまとめて答える。どちらも標準）
  - 「段階②-1 へ。関わり方は なし」（上位のモデルの利用枠を使わないとき。段階②-1 は 〈主〉 のセッション）
  - 「段階②-1 へ。関わり方は (B)。段階②-2 は (C) で、移る前に (B) を一回」（利用枠を抑えつつ、上位のモデルの目を借りるとき）
  - 「段階②-2 へ。関わり方は (A)」（セッションのモデルは、段階②-1 と同じなので切り替えは要らない。新しいセッションで §1.4 の一言を貼る）
  - 「段階② へ。②-1 と ②-2 をまとめる。関わり方は (A)」（§1.9 の一言で始める。利用枠を抑えるなら、なし、判定の周から (C)）
  - 「まだ移らない。<足りないこと> をしてから」
- 返事を受けたセッションは、HANDOFF.md の §0 の「今の段階」と「次の段階」を直し、コミット・push してから止まる。

## 3. 合図の早見

| 送る言葉 | いつ | 何が起きる |
|---|---|---|
| 〈合図の語〉（このリポジトリでは ultracode） | 段階③ で、主担当が「〈合図の語〉 で相談しますか」と聞いた論点への返事。または論点を名指しして頼むとき | その論点だけを、ワークフローで相談役に相談する |
| 「はい」 | 段階①-2・②-2 の (C) の「相談しますか」に／相談のあとの確認の一文に | 相談する／判定どおり次の行程に進む |
| 「いいえ」・「任せる」 | 相談の問いに | 主担当がおすすめで決め、「相談なし」を記録して進める |
| 「<束> を掘る」・「任せる」 | 段階②-1 の一周目のあと、「どの束をもっと掘りますか」に | 二周目の観点を、選んだ束（任せるなら、空いた部分と足りない種類）に寄せる。採るかどうかではない |
| 「〈上〉 主」「〈上〉 総合」「〈上〉 要所」「〈上〉 なし」 | 段階①-2・②-1・②-2 で関わり方を変えるとき（段階②-1 では 主・総合・なし だけ）。標準は 主。段階③ では 〈合図の語〉 と一緒に（総合・要所だけ） | 関わり方が変わる。主 に変える・外すときは、主担当が HANDOFF.md に書いてコミット・push してから、モデルの切り替えを頼む（新しいセッションで、同じ一言から始める） |
| 「（この依頼の中の『〈合図の語〉』は説明の語です）」 | 決まりを話す、引用するとき | ワークフローを起こさない |

## 4. ワークフローのひな形の渡し方

Workflow ツールに、`scriptPath`（ファイルの絶対パス）と `args` を渡します。model は、CLAUDE.md の役割の表の指定をそのまま書きます（省かない）。

相談（相談役。CLAUDE.md の「相談の手続き」の 2。段階①-2・②-2 の関わり方 (B) なら `lenses` を省くと五つの観点になる。段階②-1 の (A)(B) は `lenses` を渡す。散文の見立てを返させるときは `"form": "analysis"`。下の注）：

```
scriptPath: <このリポジトリ>/docs/operating-kit/workflows/consult.js
args: {
  "topic": "<論点>",
  "background": "<迷っている理由・案・おすすめ>",
  "read": ["CLAUDE.md の「段階」", "HANDOFF.md §4", "docs/plan-<名前>.md §5"],
  "role": "相談役",
  "model": "<役割の表の相談役（基本）の指定>",
  "effort": "xhigh"
}
```

段階②-1 の (A) の始めの問いの立て直し（主担当が先に、問いの言い換え・parts・観点の案を考察ノートに書いてから。`model` は役割の表の (A) の相談役の指定）：`"form": "analysis"`、`read` に地図と一覧（constraints.md を除く）、`background` に主担当の parts と観点の案（言い換えは書かない）、`lenses` は `[{ "key": "問いを言い換える", "ask": "<対象を別の問いに言い換える>", "blind": true }, { "key": "部分の切り方", "ask": "<parts の切り方の抜けと、別の切り方を挙げる>" }, { "key": "観点の立て方", "ask": "<観点の案の偏りと、足す観点を挙げる>" }]`。「問いを言い換える」は blind なので、主担当の言い換えを見ずに、独立に言い換える。

段階②-1 の (B) の `lenses`（時期は二つ。docs/main-agent.md §3）：始めの問いの立て直しは、上の三つの観点を blind にしない形（`background` に主担当が立てた topic・parts・観点の案を書き、`read` に地図と一覧（constraints.md を除く）を入れる）。一周目のあとは `[{ "key": "抜けている観点", "ask": "<案の一覧に無い観点を挙げる>" }, { "key": "広げ足りない所", "ask": "<案の少ない部分と種類を挙げる>" }, { "key": "伸ばしがいのある束", "ask": "<案の一覧から、もっと掘ると実りがありそうな束と、その理由を挙げる>" }]`（blind にしない。目隠しの観点は案の一覧を読まない）。consult.js の観点は `{ "key", "ask" }` で渡す（名前だけで渡せるのは ideate.js）。

考察の観点（段階②-1。結果は考察ノートへ。広げる相には見せない）：`"role": "検討担当"`、`model` は役割の表の検討担当の指定。一周目の前は `"blind": true`、`"form": "analysis"`、`read` は地図と一覧と `sources/` で、観点は `[{ "key": "緊張関係", "ask": "<互いに引き合う要求・制約・願いを、ファイルと行で示す。どちらを取るかは書かない>" }, { "key": "原因の仮説", "ask": "<原因や前提の仮説を三つまで。それぞれ、正しければ見つかるものと、確かめ方を添える>" }, { "key": "前提と食い違い", "ask": "<材料・地図・文書の間の食い違いと、だれも確かめていない前提を挙げる>" }]`。一周目のあとは、blind にせず `read` に案の一覧を入れ、`[{ "key": "トレードオフの軸", "ask": "<案を並べる軸を二〜三立て、案の id がどこに来るかを書く。良し悪しは書かない>" }, { "key": "塊をまたぐ根", "ask": "<いくつもの案に共通する前提と、先に決めると以後が軽くなるものを挙げる>" }]`。`form: 'analysis'` の答えは、判定に使うのは `claims`（根拠つき）だけ。`hypotheses` は、確からしさの印つきの案と問いの材料（CLAUDE.md の「相談の手続き」の 3）。

検討担当に、まとまった案を疑わせる・絞る観点で見させるとき（段階①-2・②-2）：`role` を `"検討担当"`、`model` を役割の表の検討担当の指定にし、`lenses` に観点を渡す（例：`[{ "key": "案A を疑う", "ask": "…" }, { "key": "外れた案", "ask": "…" }]`）。

目隠し：案を広げさせる観点には、主担当の見立て（`background`）を見せない。`"blind": true` で全部の観点、`"blind": ["<広げさせる観点の key>"]` のように名前でその観点だけ（観点に `"blind": true` と書いてもよい）。疑わせる観点には見せる。既定の五つ（別案も）は今の案を前提にするので、blind にしない。blind にする観点は `{ "key", "ask" }` で足し、ask は今の案を前提にしない形で書く。blind を使うときは、`topic` には論点だけを書き（案・おすすめは `background` に）、`read` に HANDOFF.md、案の一覧のフォルダ（`sources/` 以外）、考察ノート、cards.md、raw-R*.json、tries/、思いつきの置き場、見送りの台帳、計画書の決めごとを入れない（`read` は全部の観点に共通。consult.js が、HANDOFF.md・案の一覧のフォルダ・notes.md・cards.md・raw-R*.json・tries/・ideas-inbox.md・ideas-shelf.md を見つけたら止める。目隠しの観点には、指示文でもそれらを読まないと伝えてある）。`"blind": true` を `lenses` を省いたまま使うと止まる（既定の五つは blind にしない）。段階③ と段階の外で、利用者が 〈合図の語〉 で名指しした論点を小さく広げるときも、相談役で広げさせる観点を blind にする（広げ直しが大きいなら、段階②-1 へ戻ることを提案する）。

発想（検討担当・調査担当。段階②-1。広げる → 照らす → 伸ばす・疑う。判定しない）：

```
scriptPath: <このリポジトリ>/docs/operating-kit/workflows/ideate.js
args: {
  "topic": "<対象と、困っている場面だけ。案・おすすめ・見立ては書かない>",
  "model": "<役割の表の検討担当の指定>",
  "lightModel": "<役割の表の、照らす相の調査担当の指定>",
  "round": 1,
  "read": ["docs/wip/<①-1 の日付>/map/README.md", "<地図のファイル>", "docs/wip/<①-1 の日付>/<話題>.md"],
  "parts": ["<地図と一覧の「部分の候補」から選んだ、対象の部分（地図に無い切り口は主担当が材料から立てる）>", "…"],
  "lenses": [
    { "key": "部分A", "ask": "<部分 A について、何を広げるか。答えの例は書かない>" },

    { "key": "部分C", "ask": "…" },

  "background": "<主担当の見立て。伸ばす・疑う相だけに見せる>",
  "mainIdeas": [{ "id": "R1-主-1", "title": "<短い名前>", "what": "<何を>", "scene": "<場面>", "kind": "<奇抜／やめる・減らす／組み合わせる／制約を外す／作らない／そのほか>", "parts": ["<部分>"], "why": "<筋道。任意>" }]

```

- 一周目は、対象の部分を観点にしたもの（`{ "key", "ask" }`）と発想の型を半分ずつほど混ぜる。`lenses` を省くと、発想の型の既定の六つ（使う人の場面・逆にする・ほかから借りる・制約を一つ外す・極端にする・ほかの立場）。ほかに名前で選べるのは、組み合わせる・時間をずらす・既知の欠陥から・問いを変える・作らずに済ませる。ふつうの計画は一周に 6 観点で、二周以上を目安にする（照らす相・伸ばす疑う相の 1 体が 8 案ほどに収まる）。小さな計画は三つで一周。一度に起こせるのは 6 観点まで（`"doubt": false` で伸ばす・疑う相を外せば 8 まで）。
- 主担当の先出しの案：`mainIdeas`（上限 16）。広げる相には見せず、照らす相と伸ばす・疑う相が通す。id は `R<周>-主-<番号>`（round と合わせる）。`only` と一緒には渡せない。`known` に同じ id を入れない。返す値の `counts.main` は `{ total, unique }`（unique は、広げた案のどれとも重ならなかった数）。
- 案の欄：広げる相は 1 観点 4〜6 案を目安に 12 まで返す（`more` が真の観点は、二周目でその観点を掘る。`only` で頼み直さない：同じ id に別の案が入る。`only` で頼み直すのは、広げる相が空だった観点だけ）。各案に任意の `why`（筋道。推し量り）。観点の外の考えは `aside` に自由文で返り、返す値の `asides` に集まる。
- つなぐ一体：`"synth": true`。全部の案を見て、塊をまたぐ根・組み合わせた新しい案（id は `R<周>-X-<番号>`。照らしも疑いも経ていない）・観点の空白を返す（束と順位は書かせない）。体数が一つ増え、塊は 5 つまで。
- 観点ごとのモデルと読むもの：`"lensModels": { "<観点の key>": "<役割の表の指定>" }`（広げる相のその観点だけ別のモデル。返す値にモデル名は入らず、key だけ）。観点に `"readOnly": true` と `"read": [...]` を付けると、その観点は共通の `read` を読まず、自分の `read` だけを読む（観点ごとに別の地図を読ませる）。
- 深める周・逐次（二周目から）：`"deepen": ["R1-L2-3 下書きを残す：<一文>"]`（掘る方向に選ばれた束の案を、広げる相に見せる。id は `known` にも要る。fresh は null）。`"chain": true`（観点を順に一体ずつ回し、先の観点の案を後の観点に見せる。目隠しが弱まるので、その周の観点は 3 つほどに絞る。`only` と一緒には渡せない）。
- 二周目は `"round": 2` にし、観点を空いた部分と少ない種類に向けて替え、`known` に前の周までの案を「<id> <短い名前>」の形で渡す（照らす相だけが見て、同じ形で重なりを返す。広げる相には見せない。`node docs/operating-kit/tools/ideas-table.mjs known raw-R1.json …` で作れる）。一周目も、思いつきの置き場・見送りの台帳から案の一覧に載せた案があれば `known` に入れる。空だった広げる相の観点だけを頼み直すときは、`lenses` を元と同じ並びで、`round`・`parts`・`known` も元と同じに渡し、`only` に頼み直す観点の名前を書く（id が変わらない）。照らす・伸ばす・疑う相が空だった塊は頼み直さない（docs/main-agent.md §4.2）。
- `read` には、HANDOFF.md、案の一覧のフォルダの `sources/` 以外（README.md・cards.md・考察ノート notes.md・raw-R*.json・`tries/`）、地図のフォルダの notes.md、思いつきの置き場、見送りの台帳、段階①-1 の索引の「思いつき」の節を入れない（止める一覧。`sources/` の下だけ許す。ideate.js が止める。置き場と台帳は既定の名前 ideas-inbox.md・ideas-shelf.md だけ止まるので、別の名前なら主担当が入れない。map のフォルダごとも止まる。広げる相・照らす相の指示文でも読ませない。先出しの案の `ideas/main-R<周>.json` も案の一覧のフォルダなので入れない）。案の一覧のフォルダの `sources/` の材料は入れてよい。制約の一覧 `map/constraints.md` は共通の `read` に入れない（二周目からは、制約を外す方向の観点の `read` にだけ。一周目はどこにも。スクリプトが止める）。地図と一覧はパスを名指しする（HANDOFF.md を読ませないので、担当は §0 からたどれない）。`effort`・`lightEffort` は、CLAUDE.md の役割の表に指定が無ければ省く。

下調べ（調査担当。段階①-1 など）：

```
scriptPath: <このリポジトリ>/docs/operating-kit/workflows/survey.js
args: {
  "scope": "<HANDOFF.md の §0 の「次の段階」に書いた範囲>",
  "model": "<段階①-1 は「段階①-1 の決まり」の 6 の指定。ほかの段階で読み足すときは、役割の表の調査担当の指定>",
  "topics": [
    { "key": "話題A", "ask": "<集めること>", "read": ["<読む場所の手がかり。利用者が渡した資料のパスも>"] },
    { "key": "周辺の話題", "ask": "<集めること>", "periphery": true }
  ],
  "external": false
}
```

`key` は話題の短い名前（ファイル名になるので、`/ \ : * ? " < > |` は使えない）。`external` を `true` にするときだけ、`"externalScope": "<利用者が許した範囲>"` を足す（`external` が `false` のときに `externalScope` を渡すと止まる）。

- 返す値の `others`（外の事例・使う人の場面・類推。出どころの種類と確からしさの印つき）は、事実（`facts`）と節を分けて書く。`snags`（引っかかり）は索引の「引っかかり」の節に。`periphery` は一話題まで。`external` は、利用者が外の資料（Web など）を許したときだけ `true` にし、`externalScope` に許した範囲を書く（CLAUDE.md の「段階①-1 の決まり」の 4）。利用者が渡した資料は、リポジトリの外のパスでも `read` に入れれば読める（許しは要らない）。

- 結果は、通知の本文ではなく、consult.js・survey.js は journal.jsonl の全文（体ごとの答え）を読む。ideate.js は、出力のファイルの `result` の全文（id を振った返す値）を読み、journal.jsonl は空や失敗の理由を見るときに読む。相談の答えに null があれば、failures と journal.jsonl で理由を確かめる（利用枠の制限なら、同じ args で model だけ代わりの指定にして頼み直す。ideate.js は、空だった広げる相の観点を `only` で頼み直すだけにする。同じ args で起こし直すと、同じ id に別の案が入る）。consult.js・survey.js の返す値の `model` は、記録やファイルに写さない。
- 一つのワークフローは 10 体以内（スクリプトが止める）。consult.js の観点と survey.js の話題は 10 まで。ideate.js だけは 18 体以内で、一度に起こす観点が 6 まで（広げる 6 と、8 案ずつの塊ごとの照らす・伸ばす疑う 6 ずつ。つなぐ一体を足すときは、塊が 5 つまで）。
