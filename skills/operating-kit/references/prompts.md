# 段階ごとの一言と、合図の早見（運用の型）

- 作成：2026-10-15。新しいセッションの最初に貼る文と、会話で送る短い言葉をまとめました。型の説明は [README.md](README.md)。
- 文は CLAUDE.md の節の名前で書いてあるので、この型を入れたリポジトリなら、そのまま貼れます。`< >` の所だけ埋めてください。
- セッションのモデルと ultracode（〈合図の語〉）は、貼る前に使う人が CLAUDE.md の段階の表のとおりに設定します。新しいセッションは、同じフォルダか作業枝で始めます。
- モデル名は書きません。合図の言葉の〈上〉は、CLAUDE.md の「関わり方」の表にある言葉に読み替えてください。

### 1.8 型だけを使う一言（CLAUDE.md の無い場所や、一回きりの相談で）

> この会話では、次の決まりで進めてください。(1) あなたは主担当で、計画・判断・確かめを自分で行う。(2) 迷う重要な論点（決めきれない案が二つ以上あり、選び違えると戻すのが重いもの）では止まり、論点・迷う理由・案・おすすめ（一つ）を書いて「〈合図の語〉で相談しますか」と聞く。私が〈合図の語〉と返したときだけ、上位のモデルに読み取り専用で相談し、結論と根拠だけを受け取る。説明や引用の中の語では動かない。(3) 相談の結論は決定ではない。票で決めず、割れたら両側の根拠を自分で読んで判定する。(4) 大きな決めごとは私が決める。問いは三つまで、おすすめ付き。(5) モデルと effort は私が切り替える。あなたは切り替えない。(6) 確かめていないことは、そう書く。(7) 案を出すときは、先に判定なしで観点ごとに広げて一覧にし、そのあとで判定する。

### 1.9 段階②-1 と ②-2 を一つのセッションでまとめるとき

> あなたは主担当で、段階②（②-1・②-2 をまとめる）のセッションです。CLAUDE.md と docs/main-agent.md を読み、方針を 3 行で言い直してください。HANDOFF.md の §0・§3・§4.2 を読み、§0 の「今の段階」と、このセッションの設定・枝が合うかを照らしてください。対象は <依頼>。まず §1.3 の進め方で案を広げ、案の一覧をコミットしてから、§1.4 の進め方で判定と計画に進んでください（docs/main-agent.md §2.6）。終わりの目安は 1 と 2 だけを照らします。終わったら「移ってよい」と提案して止まってください。

## 2. 移るときに送る言葉

- 「移ってよい」の提案への返事の例：
  - 「段階①-2 へ。関わり方は なし」
  - 「段階②-1 へ。関わり方は なし。段階②-2 は (C) で、移る前に (B) を一回」（段階①-2 から、二つの段階の関わり方をまとめて答える）
  - 「段階②-1 へ。関わり方は (B)」
  - 「段階②-2 へ。関わり方は (A)」（このあと、使う人がセッションのモデルを (A) のものにして、§1.5 の一言で始める）
  - 「段階② へ。②-1 と ②-2 をまとめる。関わり方は なし、判定の周から (C)」（§1.9 の一言で始める）
  - 「まだ移らない。<足りないこと> をしてから」
- 返事を受けたセッションは、HANDOFF.md の §0 の「今の段階」と「次の段階」を直し、コミット・push してから止まる。

## 3. 合図の早見

| 送る言葉 | いつ | 何が起きる |
|---|---|---|
| 〈合図の語〉（このリポジトリでは ultracode） | 段階③ で、主担当が「〈合図の語〉 で相談しますか」と聞いた論点への返事。または論点を名指しして頼むとき | その論点だけを、ワークフローで相談役に相談する |
| 「はい」 | 段階①-2・②-2 の (C) の「相談しますか」に／相談のあとの確認の一文に | 相談する／判定どおり次の行程に進む |
| 「いいえ」・「任せる」 | 相談の問いに | 主担当がおすすめで決め、「相談なし」を記録して進める |
| 「〈上〉 主」「〈上〉 総合」「〈上〉 要所」「〈上〉 なし」 | 段階①-2・②-1・②-2 で関わり方を変えるとき（段階②-1 では 主・総合・なし だけ）。段階③ では 〈合図の語〉 と一緒に（総合・要所だけ） | 関わり方が変わる。主 に変える・外すときは、主担当が HANDOFF.md に書いてから、モデルの切り替えを頼む |
| 「（この依頼の中の『〈合図の語〉』は説明の語です）」 | 決まりを話す、引用するとき | ワークフローを起こさない |

## 4. ワークフローのひな形の渡し方

Workflow ツールに、`scriptPath`（ファイルの絶対パス）と `args` を渡します。model は、CLAUDE.md の役割の表の指定をそのまま書きます（省かない）。

相談（相談役。CLAUDE.md の「相談の手続き」の 2。関わり方 (B) なら `lenses` を省くと五つの観点になる）：

```
scriptPath: <このリポジトリ>/docs/operating-kit/workflows/consult.js
args: {
  "topic": "<論点>",
  "background": "<迷っている理由・案・おすすめ>",
  "read": ["CLAUDE.md の「段階」", "HANDOFF.md §4", "docs/plan-<名前>.md §5"],
  "role": "相談役",
  "model": "<役割の表の相談役（基本）の指定>",
  "effort": "xhigh"
}
```

検討担当に案を広げさせる・疑わせるとき：`role` を `"検討担当"`、`model` を役割の表の検討担当の指定にし、`lenses` に観点を渡す（例：`[{ "key": "案A を疑う", "ask": "…" }, { "key": "外れた案", "ask": "…" }]`）。

下調べ（調査担当。段階①-1 など）：

```
scriptPath: <このリポジトリ>/docs/operating-kit/workflows/survey.js
args: {
  "scope": "<HANDOFF.md の §0 の「次の段階」に書いた範囲>",
  "model": "<役割の表の調査担当の指定>",
  "topics": [
    { "key": "<話題>", "ask": "<集めること>", "read": ["<読む場所の手がかり>"] }
  ]
}
```

- 結果は、通知の本文ではなく journal.jsonl の全文を読む。相談の答えに null があれば、failures と journal.jsonl で理由を確かめる（利用枠の制限なら、同じ args で model だけ代わりの指定にして頼み直す）。
- 一つのワークフローは 10 体以内（観点・話題は 10 まで。スクリプトが止める）。
